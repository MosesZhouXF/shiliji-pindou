# 拾粒集 · 拼豆图纸工作台

纯浏览器图片转换工具。无需 API Key、后端或安装依赖；原图不上传。

## 本地运行

在本目录运行 `npm run dev`，打开 http://127.0.0.1:5173 。需要 Node.js 20 或更新版本。

`npm test` 运行转换引擎测试，`npm run check` 检查 JavaScript 语法。`dist/` 可直接部署到支持 ES modules 和 Web Worker 的静态托管服务；请通过 HTTP 打开，不使用 `file://`。

## 使用

1. 上传或拖入 JPG / PNG / WebP（最大 20 MB，最多 4000 万像素），或使用内置示例。
2. 选择算法、长边格数（16–160）、用色上限（2–48）；保持原图宽高比例，自动重新生成。
3. 默认开启“移除纯色外背景”和“主体铺满图纸”，裁掉外围透明留白，保持原画布比例，四周约留一格。可关闭以保留原构图。也可查看原图、放大图纸、显示网格和色号；鼠标位于画布区域时，滚轮向上放大、向下缩小，最小 50%，放大不设比例上限，侧边面板保持正常滚动。
   “原图预处理”可选择关闭、轻度、标准、加强。先在较高分辨率下做保边平滑、平涂分色和边界整理，再采样到网格；可切换“原图 / 预处理图 / 拼豆图”检查中间结果。
4. 画布左侧的手形按钮用于拖动图纸，电脑和手机均支持；悬停在格子上仍可查看色号。电脑也可按住鼠标中键拖动，手机在任意工具下均可双指缩放和移动，缩放最小 50%，放大不设比例上限；点击“适应”恢复居中。色号使用矢量文字显示，放大保持清晰；点击画布右下角“全屏”进入全屏工作区，可点击“退出全屏”或按 Esc 返回。画笔、橡皮、油漆桶和吸管保留单指编辑，切换为双指手势时取消本次触摸笔画。颜色按钮显示当前画笔色，点击可打开完整色板。油漆桶只填充上下左右连通的同色区域，支持透明区域，并可一次撤销。撤销 / 重做支持按钮及 Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z。
   工具栏的“颜色替换”按钮可直接打开替色面板；左下角“图纸处理”面板包含一键整理、只保留主体、清理浅色外边、色块简化和自动描边。这些是可撤销的一次性操作，也可用于导入的工程图纸；修改转换参数不会自动重复执行。颜色替换从图纸实际用色选择原色，从当前色板选择目标色，预先显示格数，整图替换所有同色区域并更新用量，支持一次撤销；选色面板显示色块、色号和 HEX。
5. 导出包含坐标、色号、十格分段和用量图例的高清 PNG、SVG 矢量图纸、备料 CSV 或可再次导入的 JSON 工程。

PNG 按每格 56 像素绘制，较大图纸会按最长 4096 像素、总计 1600 万像素以内缩小，以兼容手机内存。SVG 保留完整矢量网格和文字，适合大尺寸打印和任意倍率查看；导出不受画布当前缩放比例影响。

重新转换会替换精修结果，可通过撤销恢复前一张图纸。关闭页面前保存工程。工程保存网格和色号，不保存原图；导入工程后仍可精修，重新转换需再次上传原图。手工精修可以增加颜色，用色上限仅限制自动转换。

桌面端参数面板、画布和用色列表独立滚动，调整长参数列表不会移走画布。窄屏画布顶部常驻“导入图片”按钮，可直接导入图片或工程；通过预览区的“参数 / 用色及导出”按钮打开对应面板。

## 算法

| 模式 | 方法 | 适合 |
| --- | --- | --- |
| 卡通保边 | 格内 RGB 颜色分组 + 主色采样；占比足够的深色轮廓优先 | 动漫、插画 |
| 描边平涂 | 主体白边分离、线稿/色块分层、区域平涂、轮廓强化与中心线保留 | 带描边的手绘插画 |
| 照片保真 | 在线性光空间做区域平均 | 人像、宠物、摄影 |
| 结构抽象 | 3 倍网格采样，基于 Lab 颜色与位置的局部区域分配，迭代 3 次 | 需要简化的复杂图片 |
| 黑白线稿 | 局部深色保护 + 固定亮度阈值 | 简单线稿、单色标志 |
| 像素原样 | 中心点采样，不做平均和杂点清理 | 已有像素画 |

结构抽象是 **SLIC 启发的轻量版本**，不是 [Pixelated Image Abstraction](https://cragl.cs.gmu.edu/pixelate/) 的完整复现；没有实现论文的联合调色板退火。所有模式共用 Lab / CIEDE2000 色差匹配；当初始匹配颜色超限时，用加权感知误差降低量贪心选取真实色板子集。可选杂点清理仅合并四邻域中至少三个同色且色差小于 14 的孤立点，保护高对比特征；默认不做抖动。

外背景处理使用四角一致性检查与边缘连通洪泛，只适用于近似纯色背景。四角颜色不一致时保留背景并提示，不是通用 AI 抠图。

主体铺满在背景处理后、网格采样前执行，适用于去背景图片与透明 PNG。原有模式通过八邻域连通区域定位主体，忽略零散小点对裁边的影响，保留显著的其他主体与邻近装饰；再按原画布宽高比裁切，预留约一格边距。描边平涂则按内容包围盒比例生成网格，长边遵循格数设置。不拉伸图案。复杂构图下可关闭此选项以保留完整构图。

“只保留主体”在当前网格中按八邻域识别所有非透明格子的连通区域，仅保留格子数量最多的一块，清除所有其他区域，不移动或缩放主体。不同颜色之间也可连通；面积相同时保留从左上开始首先遇到的一块。对于有背景的图片，先移除背景再执行此操作。

“自动描边”使用指定 MARD 色号，在当前图案的外侧添加一格宽的描边，使用八邻域扩张；只涂外部连通的透明格，不覆盖原有颜色或填充封闭孔洞。每点击一次增加一圈，画布格数不变，贴边处仅填充画布内可用格子。描边色参与实际用色和用量统计，手动操作可以超出自动转换的用色上限。

“清理浅色外边”在描边前使用：每次仅删除外缘一格宽的白色/近白色格（Lab 亮度 L≥92、色度 C≤14），连续点击可逐层清理，支持撤销。内部白色和封闭孔洞周围的白色不参与清理；外露的浅色衣服也可能被削去一格，应根据预览决定清理次数。已描边时先撤销描边，再清理浅色外边并重新描边。该功能不使用语义识别，不能自动判断白色是否属于衣服。

“色块简化”是可撤销的一次性操作：轻度最多 18 色、标准最多 12 色、加强最多 8 色。先在当前已用色中按感知色差选取少量颜色，再以原始色差引导四邻域标签优化，最后将低色差小区域合并到相近的大色块。保持每个格子的透明/非透明状态、画布尺寸和拼豆颗数，输出不会引入未使用过的色号。小区域合并避免同频颜色相互交换；高对比的眼睛、高光等细节受色差约束保护，但减色仍可能改变细节配色。建议先试标准，想保留更多层次时选择轻度。可以用于已导入工程；建议在描边前使用，后续描边可能新增一色。

此简化实现是颜色量化、边缘加权邻域优化与小色块合并的组合，不能识别人脸语义，也不是 PIA 的完整实现。关于低分辨率下结构与调色板需要共同考虑的研究，见 [Pixelated Image Abstraction with Integrated User Constraints](https://cragl.cs.gmu.edu/pixelate/journal.html)。

## 描边平涂

适合带描边的手绘插画。分离透明区、外围白边和内部白色后，将线稿与色块分别处理：按中性/彩色连通区域平涂，适度强化外轮廓，通过小线条中心线保留五官，再合成并匹配当前 MARD 色板。细小排线按单格面积抑制，减少脸颊短线与眼睛黏连。

模式内可调外轮廓强度、细节保留程度、色块简化程度和描边颜色。描边色与手动“自动描边”独立，选色面板显示色块、色号和 HEX。切换模式保留当前格数和用色设置，不覆盖其他模式的预处理参数。描边平涂使用独立处理流程，隐藏普通预处理与杂点开关；“预处理图”可查看分层整理后的工作图。

`dist/flat-worker.js` 按需加载随站部署的 OpenCV WebAssembly 并运行 `dist/flat.js`，原图始终留在浏览器内。依赖锁定为 `@techstark/opencv-js@5.0.0-release.1`，原始包完整性校验、文件 SHA256 与 Apache-2.0 许可证位于 `dist/vendor/`。该组件约 13 MB，仅选择此模式时加载；普通模式不加载。每次转换都释放临时 OpenCV 对象，取消转换会结束对应 Worker。

工作图长边最多 960 像素，每格 4–12 个样点；全局聚类采样最多 160000 点以限制大图开销。输出可编辑工程、统计和导出沿用原有格式。该流程不进行语义重绘，不能保证在低格数下复现重绘图中的表情和比例。

## 原图预处理（纯本地）

开启后，浏览器先将输入长边规范到 512–768 像素的工作尺寸（不放大小图），再处理背景和主体留白。随后在降到拼豆网格前，执行 Lab 引导的双边平滑、加权 Lab 聚类分色、低对比边界多数滤波。轻度、标准、加强分别进行 1/2/3 轮平滑，最多使用 20/16/12 种源图代表色；深色代表色锚定以保护墨线。最终仍按设定的网格算法和 MARD 用色上限生成图纸。加强档可能丢失表情与细节，卡通插画建议从轻度或标准开始。已有像素画建议关闭。

处理运行在 Web Worker；预处理保持工作图每个像素的 alpha，透明区域不参与滤波或聚类，不扩散背景色。预处理预览和对应网格一起更新，撤销再生成时能恢复对应预览。预处理后的图片保留在当前浏览器内，工程 JSON 仍只保存可编辑网格，不包含原图和预处理预览。该算法不进行语义重绘，不能保证达到手工像素重绘示例的造型；它主要压制纹理和碎色。

保边平滑与平涂分区的研究参考：[Real-Time Video Abstraction](https://cs.colby.edu/courses/S19/cs365/papers/winnemoller-videoAbstraction-SIG06.pdf)、[PosterChild](https://cragl.cs.gmu.edu/posterchild/)。本实现是轻量处理流程，未完整复现这些论文。

转换运行在独立 Web Worker 中，参数变化取消旧任务，避免旧结果覆盖新结果。暂未集成 AI 重绘、通用语义抠图或多品牌色板。

## 数据与边界

- `dist/palette.json`：291 个 MARD 色号；数据复用本地 `image-to-pindou` 技能随附的 `palettes/mard-291.csv`。屏幕 RGB 是参考值，未进行实体色卡校准。
- 默认使用 MARD 221 色（A26、B32、C29、D26、E24、F25、G21、H23、M15），色号范围核对自[公开色板数据](https://github.com/HansBug/pindou-color-data/blob/main/mard-221-github/colors.json)，RGB 延用本项目已有数据。可切换 291 色扩展版，以及从 221 色按 Lab 颜色覆盖选出的 144/96 色精选组合；精选组合不是官方套装。
- `dist/palettes.js`：色板目录和精选组合。转换、画笔与描边都使用当前色板；工程记录色板 ID，导入旧工程时默认按原有 291 色恢复。描边色通过带色块、色号、HEX 和搜索的面板选择。
- `dist/sample.svg`：本项目创建的矢量示例插画。
- `dist/engine.js`：不依赖 DOM 的转换与工程校验。
- `dist/worker.js`：浏览器后台转换入口。
- `dist/app.js`：导入、编辑、撤销与导出。
- 字体使用本机系统字体，不依赖 Google Fonts 等外部字体服务。
- 尺寸按 5 mm 拼豆估算，不包含底板边缘。实际图纸长边可能因极端长宽比形成很窄的另一边。
